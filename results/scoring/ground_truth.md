# 评测题人工判分依据（T01–T08）

> 评测题无公开答案，以下 ground truth 由本人阅读 `基础/data/cases.json` 中每题的 7 段原文人工确定。
> 每条给出「规则出处 + 候选数据 + 应用过程」。K 条件只给 2 段（由 `starter/lexical.py` 词法选出），
> 当规则/互补证据被漏掉时，正确行为是答“证据不足”。

## 判分口径说明

- **full** = R0 / R1 / R2 / improved：给完整 7 段，答案可由原文推导。
- **K** = 词法检索前 2 段：若 2 段不足以建立命题，正确答案为“证据不足”。
- 技术失败(status≠ok)、格式错误(answer 无法解析) 一律保留在分母，不剔除。
- 命名类别名：T07 的“方案丙”接受“丙”（模型已选对对象，仅省去“方案”前缀），判为 `correct_alias`。
- 引用语义支撑(cite_support) 由本人逐条读原文核验，规则与逐题结论见文末「引用支撑核验」。

## 引用支撑核验（cite_support，本人逐条读原文）

核验的是「模型引用的段落是否在语义上支撑它给出的答案」，与「答案对错」分开（参考 ALCE 把正确性与引文支持分开评价）。
判据：每题的「关键段落」= 足以推导出正确答案的最少段落集合（见 `score.py` 的 `REQUIRED_EVIDENCE`）。
四档结论：

| 结论 | 含义 | 本批出现 |
|---|---|---|
| `supported` | 引用足以支撑答案（含正确拒答“证据不足”） | 26 |
| `contradicted` | 引用本身与答案矛盾——引了规则+候选却答错/答“证据不足” | 13 |
| `insufficient` | 引用相关但缺关键段——答对却只引候选、漏引规则段 | 1 |
| `not_checked` | 未核验 | 0 |

逐题结论：

- **T01（答 S24）**：full 条件下 4 次全答“证据不足”且都引了规则 P761989 + 候选 P555495 → `contradicted`（规则+候选足以推出 S24）。K 只引 P555495+P130348、缺规则 → 正确拒答 → `supported`。
- **T02（76%）**：full 4 次引分母 P552476 + 分子 P169676 → `supported`。K 引 P552476+P500295、缺分子 → 正确拒答 → `supported`。
- **T03（2.6）**：full 4 次引 P385105+P362285 → `supported`。K 缺候选 P362285 → 正确拒答 → `supported`。
- **T04（流程乙）**：R0/R1/improved 答“流程丙”却引规则 P660995（错误≤3）+候选 P758661（丙 5 条错误）→ 与答案矛盾 → `contradicted`；**R2 答“流程乙”正确但只引候选 P758661、漏引规则段 P660995 → `insufficient`**；K 缺规则 → 正确拒答 → `supported`。
- **T05（真·证据不足）**：8 次全部正确拒答；资料本身无任何能耗数据，无论引哪些段落都支撑“证据不足” → `supported`。
- **T06（25%）**：P873502 已含 60/45/8/7，5 次全部 `supported`（K 只引 P873502 也足以推导）。
